## 正确刷新顺序

1. 读取 get_editor_state，核对真实工程/版本/场景。Play 切换菜单是 toggle，不能盲重试。
2. 修改资源/编译前，若正在 Play，经 execute_menu_item `{"menu_path":"Edit/Play"}` 退出一次，再确认。
3. 源文件修改后 execute_menu_item `{"menu_path":"Assets/Refresh"}`。应用在后台时自动刷新曾不可靠。
4. Domain reload 可暂时断开端口；等后重试只读状态。Mutation 超时可能已经生效，先观察再决定是否重试。
5. 查编译与新修订号，再进入 Play。旧内存程序集不能证明新源文件有效。

prepare_editor 曾因 editor-operations.json.tmp 共享冲突失败；用正常 Assets/Refresh，不破坏操作日志。工作区 invoke_code.py 默认 skip_refresh=true，需提前导入。

## 证据命令

- capture_game_view 参数：`{"width":667,"height":1334,"save_to_file":true,"output_path":"RecoveryEvidence/tutorial-check.png"}`，之后实际查看图像。
- get_console_logs：`{"log_type":"error","count":20,"since_seconds":120,"group_duplicates":true}`，只说明最近缓存情况。
- isPlaying=true、isPaused=false 但 Time.time/frameCount 不动时，核对 Application.runInBackground、PlayerSettings.runInBackground 和 Game View 焦点，再验证帧推进。
- simulate_mouse_drag 返回 dispatched 不证明真实跨帧输入。必要时用录像或跨帧输入状态，保留具体状态变化。

## 本次踩坑

- File.WriteAllText 在 execute_code 中被严格检查拒绝。用返回值、日志或 SessionState 存测试状态，再用正常外层文件工具保存输出。不得关闭 safety_checks 来绕过。
- Vector2/Vector3 直接交给 Json.NET 会因 normalized 等属性自引用；用数值数组/DTO。
- EditorApplication.update 需要 EditorApplication.CallbackFunction，System.Action 不能直接订阅。
- 避免打印 Unity/Hub 完整命令行，可能含临时令牌；只读取所需属性。

电脑控制只是需要时查看模拟器/编辑器实际窗口，不代替 MCP 的工程状态证据；遵循当前可用电脑控制工具和用户授权。
